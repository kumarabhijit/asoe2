Layer 1 · Do this first
Azure AD + OAuth 2.0 — Identity & Permissions
Everything else depends on this. Without an Azure App Registration and proper OAuth scopes, nothing can touch any mailbox.
App Registration OAuth 2.0 Delegated Flow Required Scopes Token Storage (DB) Token Refresh Service
Azure App Registration
  • Go to portal.azure.com → Azure Active Directory → App Registrations → New
  • Set redirect URI to your backend callback: https://yourdomain.com/api/auth/outlook/callback
  • Generate a Client Secret — store in env as AZURE_CLIENT_SECRET
  • Copy the Application (client) ID and Tenant ID into your .env file
Required First External — Azure Portal
OAuth 2.0 Delegated Flow
User clicks "Connect Outlook" → Redirect to Microsoft login → User consents to scopes → Callback with auth code → Exchange for access + refresh token
  • Use MSAL for Node.js: npm install @azure/msal-node
  • Access tokens expire in 1 hour — store refresh tokens per-user in your DB
  • Implement a token refresh middleware that auto-renews before expiry
New route: /api/auth/outlook
Required Microsoft Graph API Scopes
  • Mail.Read — read emails from the user's mailbox
  • Mail.Send — send emails on behalf of the user
  • Mail.ReadWrite — move emails, mark as read, update flags
  • offline_access — required to receive refresh tokens (do not omit)
  • Optional: MailboxSettings.Read — for out-of-office/signature info
Request minimum scopes only
Token Storage — New DB Columns on users table
  • Add: outlook_access_token TEXT — encrypted at rest (AES-256)
  • Add: outlook_refresh_token TEXT — encrypted, never expires unless revoked
  • Add: outlook_token_expiry TIMESTAMPTZ
  • Add: outlook_connected BOOLEAN DEFAULT false
  • Add: outlook_email TEXT — the connected mailbox address
  • Use pgcrypto or application-level AES-256 — never store plaintext tokens
DB Migration Required
Token Refresh Service
  • Create src/middleware/outlookAuth.js
  • Before every Graph API call, check: token_expiry < now + 5min
  • If true, call Microsoft token endpoint with refresh token to get new access token
  • Update DB with new access token and expiry — completely transparent to the user

Layer 2 · Core services
Backend — Node.js/Express Services
New services, routes, and AI agent extensions within your existing Express API.
Microsoft Graph SDK Email Sync Service Webhook Subscription Send Email API Routes Order ↔ Email Linkage AI Email Agents
Microsoft Graph SDK — Wrapper Service
  • Install: npm install @microsoft/microsoft-graph-client
  • Create src/services/graphClient.js — initializes client with user's access token
  • Exposes: getMessages(), getMessage(id), sendMessage(), replyMessage()
  • All Graph calls go through this service — never call the Graph API directly from route handlers
New: src/services/graphClient.js
Email Sync Service — Two Strategies
  • Polling (simpler, MVP): Cron job every 2–5 min calls Graph API to fetch messages since last sync, upserts into DB. Use node-cron package.
  • Webhooks (real-time): Subscribe to Graph change notifications — Microsoft POSTs to your endpoint when new mail arrives. Requires public HTTPS.
  • Recommendation: Start with polling for MVP, upgrade to webhooks post-launch
  • Create src/services/emailSync.js with the polling loop and last-sync-cursor in DB
New: src/services/emailSync.js npm install node-cron
Webhook Subscription (real-time option)
  • POST to https://graph.microsoft.com/v1.0/subscriptions with changeType: "created,updated"
  • Set notificationUrl to https://yourdomain.com/api/webhooks/outlook
  • Subscriptions expire in 3 days — need a renewal cron to re-subscribe automatically
  • Microsoft sends a validation token first — your endpoint must echo it back within 10 seconds
  • Validate incoming calls with the webhook HMAC secret before processing payload
Requires Public HTTPS URL Post-MVP complexity
New API Routes
  • GET /api/emails — paginated inbox with filters (unread, linked to order, direction)
  • GET /api/emails/:id — single email with full HTML body + attachments
  • POST /api/emails/send — send new email via Graph API on behalf of user
  • POST /api/emails/:id/reply — threaded reply, maintains Graph conversation ID
  • PATCH /api/emails/:id — mark read/unread, flag, archive
  • POST /api/emails/:id/link-order — associate email with a price hold order

Order ↔ Email Linkage Logic
  • During sync, run keyword extraction: match customer name, PO number, SKU against email subjects/bodies
  • Auto-suggest link if confidence > 80% — user confirms in UI (never auto-link silently)
  • Store in order_emails junction table: order_id, email_id, linked_by, linked_at, link_type
  • Linked emails surface inline on the existing order detail sidebar in ASOE
New Junction Table Extends order detail sidebar
AI Email Agents — Extensions to Existing Agent Layer
  • New: callEmailDraftAgent(order, email, tone) — drafts customer-facing response using order context
  • New: callEmailClassifyAgent(emailBody) — classifies inbound email by root cause (PROMO_EXPIRED, EDI_MISMATCH, etc.)
  • Both route through your existing /api/agent/* proxy — no new Anthropic API key exposure
  • Track usage in the existing AI cost tracking table — no schema changes needed
  • Human always reviews AI drafts before sending — the agent drafts, never sends autonomously

Layer 5 · Security & ops
Security, Env Vars & Deployment
New environment variables, encryption requirements, and Docker/deployment notes.
New .env Variables Security Requirements Docker / Deployment Notes
New Environment Variables
  • AZURE_CLIENT_ID — from Azure App Registration
  • AZURE_CLIENT_SECRET — from Azure App Registration (never expose client-side)
  • AZURE_TENANT_ID — your org's tenant ID, or "common" for multi-tenant
  • AZURE_REDIRECT_URI — your OAuth callback URL
  • TOKEN_ENCRYPTION_KEY — 32-byte key for encrypting stored tokens in DB
  • WEBHOOK_SECRET — to validate incoming Microsoft Graph webhook calls
Add to .env.example
Security Requirements
  • Encrypt access + refresh tokens at rest using AES-256 — never store plaintext
  • Scope the OAuth consent to the minimum required permissions only
  • Render all email HTML bodies in sandboxed iframes — prevents XSS from attacker-crafted emails
  • Rate limit the email send endpoint: max 20 sends per user per hour
  • Audit log every sent email: sender, recipients, timestamp, linked order ID
  • Webhook endpoint must validate Microsoft's HMAC signature before processing any payload
Non-negotiable before production
Docker & Deployment
  • Add email sync cron as a separate worker container in docker-compose.yml, or run inside the API container with node-cron (simpler for MVP)
  • Webhook endpoint requires a public HTTPS URL — update nginx/Traefik config accordingly
  • Add all 6 new env vars to your deployment secrets manager (Railway, Render, Fly.io, etc.)
  • Graph webhook subscriptions expire every 3 days — add a renewal cron job to avoid silent gaps
Webhook renewal cron required
