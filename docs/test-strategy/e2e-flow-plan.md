## Why this doc exists

The sibling `eng-review-test-plan.md` amendment v1.1 closed three real-world UI bugs (V1 context-aware navigation, V2 affordance regression, V3 inconsistent click semantics) by adding a W6 chrome-invariant test and a W7 Playwright flow registry. The amendment was authored from an engineering angle: registry of routes, registry of flows, YAML shape, runner.

A design-eye pass on that amendment surfaced gaps the engineering shape doesn't speak to: how flows are organised, what happens in non-happy-path interaction states, what user journey the flows are anchored to, how the chrome invariant survives a layout refactor, and what the accessibility floor is. An engineering-eye second pass then locked the implementation contract: runner architecture, fixture sourcing, chrome-invariant runtime, state-matrix tiering, aria-live convention, infra self-tests, loading-state pattern, and three additional coverage surfaces surfaced by an adversarial cross-model challenge.

## Locked decisions — design review

### D1 — Flow registry organisation

**Hierarchical directory + back-target rules at registry level.**

```
e2e/
  flows/
    onboard/
    triage/
    resolve/
    signout/
    recover/
    _registry.yaml          # back-target rules, route -> entry-path map
```

Each flow file declares `kind: golden | regression`. Golden flows protect primary user value; regression flows lock in fixes for V1, V2, V3 and successors. The `_registry.yaml` declares back-target rules generally — destination's back-target = entry-path's parent route — so the next "back button to wrong place" bug can't surface as V4 from a missing per-flow declaration. Per-flow override wins over registry rule (most-specific-precedence).

### D2 — Interaction state coverage

**State matrix per flow.**

Every flow YAML carries a `states:` array that exercises the screen at every plausible runtime condition the flow opts into:

```yaml
states: [loading, empty, error, partial_failure, stale]
state_fixtures:
  loading:           # slow API -> assert skeleton, not blank pane
    route: /api/v1/exceptions
    delay_ms: 2000
    assert_visible: '[data-testid="inbox-skeleton"]'
  empty:             # zero rows -> primary action + explanation
    route: /api/v1/exceptions
    body: []
    assert_visible: '[data-testid="inbox-empty-cta"]'
    assert_text_contains: ["You're caught up", "Refresh"]
  error:             # API 500 -> retry affordance
    route: /api/v1/exceptions
    status: 500
    assert_visible: '[data-testid="inbox-error-retry"]'
  partial_failure:   # list loads, one row fails -> degraded gracefully
    route: /api/v1/exceptions
    fixture: inbox_partial_failure
    assert_visible_count: '[data-testid="inbox-row"]'
    assert_visible: '[data-testid="inbox-row-error-marker"]'
  stale:             # status changed mid-view -> refresh prompt
    route: /api/v1/exceptions
    fixture: case_status_changed_mid_view
    assert_visible: '[data-testid="case-stale-refresh-prompt"]'
```

V1/V2/V3 were happy-path bugs. The next class lives in these unhandled states. The state matrix shape mirrors the audit-bearing-registry shape from `design.md` — one declarative artefact, generated tests.

### D3 — User journey storyboards

**Companion `JOURNEYS.md` with 3 archetypes.**

Flow registry references journey IDs. Storyboards drive coverage forward-looking, not bug-reactive.

Archetypes:
- `J1` — *new operator, day one.* Has a customer email, doesn't know which page is "the right one." 5s arc: do they orient? 5m arc: can they finish a triage? 5y arc: is the inbox a place they trust?
- `J2` — *peak-load veteran.* 30 cases queued, keyboard-driven, no time for mouse trips. 5s: does the next case load instantly? 5m: do they finish a batch without context switches? 5y: do they reach for this tool first when a critical exception lands?
- `J3` — *recovery-from-misclick.* Mis-routed a case to the wrong queue, needs to back out without losing work. 5s: do they realise the misclick? 5m: do they recover without re-entering data? 5y: does the system make recovery feel safe enough to take risks?

Each storyboard surfaces flows that need test coverage. `J2` produces the keyboard requirements in D6. `J3` produces the back-target rules in D1.

### D4 — AI slop risk

**Prefer `assert_url_equals` over `assert_url_matches` when the ID is known.**

Regex assertions like `assert_url_matches: /exception/.*` mask false-positive matches: a malformed ID like `/exception//` or `/exception/error` will pass. When the test fixture knows the exact expected URL, declare it. Reserve regex for genuine wildcards (e.g. server-generated UUIDs).

### D5 — Design system alignment

**Anchor the chrome invariant on `AuthenticatedLayout`.**

W6 currently asserts "sign-out + user-menu + breadcrumb shell" as loose selectors. A future refactor that renames `<AppShell>` to `<OperatorLayout>` could leave the assertion passing against a phantom selector match while real chrome went missing.

Rule: the chrome invariant test mounts each authenticated route and asserts the route renders inside the canonical `AuthenticatedLayout` component (or whatever asoe-ui's actual layout component is named — recon required at implementation time, before W6 lands). The component contract carries the chrome guarantees; the test asserts the contract.

### D6 — Accessibility coverage floor

**Keyboard activation + focus management in every flow.**

Every flow YAML's interactive steps must declare both a mouse action and a keyboard equivalent. Focus restoration is asserted on every navigation:

```yaml
steps:
  - action: click           # mouse path
    selector: '[data-testid="inbox-row-3"]'
    keyboard_equivalent:    # required, parallel path
      key: Enter
      focused_selector: '[data-testid="inbox-row-3"]'
  - assert_focus_on: '[data-testid="exception-detail-heading"]'   # focus moved
  - action: press
    key: Escape
  - assert_focus_on: '[data-testid="inbox-row-3"]'                # focus restored
```

Status changes (case approved, exception resolved, async errors) must trigger an aria-live announcement asserted by the flow. ASOE handles SOX-relevant traffic; a11y is a compliance posture, not a polish item.

Mobile viewport, screen-reader replay, and `prefers-reduced-motion` deferred to V2. Inbox-only keyboard would be cheaper but bets that no compliance audit lands soon — declined.

### D7 — Click modes + empty-inbox contract

**Click modes:** left-click + keyboard activation (Enter / Space) is the floor on every interactive element in every flow. Right-click context menus, multi-select (shift / cmd-click), and drag-and-drop are out of scope for V1; they land per-flow as the underlying UI ships them.

**Empty inbox:** primary action + explanation. An empty inbox is a *moment*, not a void. Test asserts both a CTA (`Refresh`, `View resolved`, etc.) and an explanatory message (`You're caught up`). This is a product decision the test plan makes explicit so the engineering team has something to assert against.

## Locked decisions — eng review (amendment v1.2, 2026-05-10)

### A1 — Runner architecture: build-time codegen + zod

`e2e/flow-codegen.ts` reads `e2e/flows/**/*.yaml` at build time, validates each via a zod schema (`e2e/flow-schema.ts`), and emits one `.spec.ts` file per flow into `e2e/flows-generated/`. Run via `bun run flows:gen` (and as a pre-commit hook). Generated specs are real Playwright tests with normal stack traces, normal IDE jump-to-definition, normal Playwright UI mode debugging. zod is TS-native — no separate ajv layer; type inference comes free.

Trace failures point at generated `.spec.ts` line numbers humans can read. Authors edit YAML; runner re-generates on save; CI runs the generated specs.

### A3 — Fixture sourcing: Playwright `page.route()` mocks

State-matrix fixtures are NOT new asoe-ui mock variants and do NOT tap asoe2 sandbox-gateway responses. Each flow's state declares an HTTP route mock inline:

```yaml
state_fixtures:
  loading: { route: /api/v1/exceptions, delay_ms: 2000 }
  error:   { route: /api/v1/exceptions, status: 500 }
```

Playwright intercepts the call before it reaches the server. asoe-ui e2e runs standalone with no asoe2 dependency. Each test gets isolated mocks per page (no cross-test pollution).

### A4 — Chrome invariant: Playwright e2e + `requiresAuth` marker

Chrome invariant moves from `tests/contract/test_authenticated_chrome_invariant.test.tsx` (RTL, won't mount Next.js App Router server components in JSDOM) to `e2e/contract/chrome-invariant.spec.ts` (Playwright). For each route in the registry, `page.goto(route)` then assert `AuthenticatedLayout` testid + sign-out + user-menu + breadcrumb shell render.

Auth route marker is an explicit `export const requiresAuth = true` in each `src/app/**/page.tsx` that needs auth. The meta-test scans `src/app/**/page.tsx` for the export; missing = test fails. (Marker is a structural completeness check, not a behavior assertion — behavior is covered by the runtime invariant.)

### A8 — State matrix tiering: per-flow opt-in + full matrix on PR

Each flow YAML declares which states are meaningful via `states: [loading, empty, error]` (an array of state keys it opts into). Validator allows omitting the matrix where it makes no sense (e.g., signout has no "empty" state). Critical-path flows (inbox, exception detail, signin) opt into all 5 states; transient flows opt into a subset. PR runs the full matrix. Nightly adds chaos states (random latency).

Opt-out from any state requires a justification comment in the YAML so reviewers can challenge it.

### Q1 — Aria-live: single `<StatusAnnouncer>` component

asoe-ui exposes one canonical `<StatusAnnouncer>` component used everywhere a status-change announcement is emitted. Stable testid `data-testid="status-announcer"` and `aria-live="polite"`. Flow YAML asserts:

```yaml
- assert_announcement_text: "Exception resolved"
```

Runner translates this to: wait for the announcer to contain the text, with a sensible timeout. One enforcement point; one selector; no per-section drift.

### T1 — Test the test infra (full coverage)

Plan adds 4 unit-test files (~150 LOC, ~1 day CC, may extend to ~1.5 days given CMT-2/CMT-3 additions):

- `e2e/__tests__/flow-codegen.test.ts` — golden-output for 1 sample YAML (input → generated spec text matches snapshot)
- `e2e/__tests__/flow-schema.test.ts` — 5 valid + 5 invalid cases against the zod schema
- `e2e/__tests__/meta-test-self-check.test.ts` — introduce a `page.tsx` without `requiresAuth` export in a fixture dir, assert meta-test fires
- `src/components/__tests__/StatusAnnouncer.test.tsx` — RTL: renders with aria-live="polite", announces text on prop change, debounces rapid announcements

Locks the test infra against silent regressions where the runner masks real bugs.

### P1 — Loading-state pattern: deferred-promise + assert-during

Runner translates `loading: { delay_ms: 2000 }` into a three-phase Playwright pattern:

```ts
let resolveRoute!: () => void;
const routePromise = new Promise<void>((r) => { resolveRoute = r; });
await page.route('/api/v1/exceptions', async (route) => {
  await routePromise;
  await route.continue();
});
const navigationPromise = page.goto('/inbox');
// PHASE 1: arrange — page is navigating, route is pending
// PHASE 2: observe-during — assert skeleton is visible while load is in-flight
await expect(page.locator('[data-testid="inbox-skeleton"]')).toBeVisible();
// PHASE 3: act — resolve and observe final state
resolveRoute();
await navigationPromise;
await expect(page.locator('[data-testid="inbox-skeleton"]')).not.toBeVisible();
```

Deterministic regardless of how fast the actual skeleton mounts. No `page.waitForTimeout` race.

### CMT-1 — A1 honored against outside-voice challenge

Adversarial subagent argued YAML+codegen will be abandoned within 3 months as escape hatches dominate, codegen breaks on Next.js/Playwright upgrades, and new engineers write `.spec.ts` directly. Counter (decisive): the design review locked YAML for the "non-engineer authors flows" property and the declarative shape that mirrors `audit_bearing_registry.yaml`; outside voice didn't engage with those properties. A1 stands. Mitigations for the rot risk: clear ownership in CODEOWNERS, `flows:gen` pre-commit hook, generated `.spec.ts` files committed to the repo for transparency.

### CMT-2 — Chrome invariant adds transition + bfcache assertions

V2 was a TRANSITION bug — chrome disappeared during forward/back navigation, not on final-state DOM. The chrome invariant as originally specified (`page.goto(route)` then assert) tests final-state only. Adding:

- For each `(route_a → route_b)` transition pair in the registry, observe chrome via `page.locator(...).waitFor({state: 'visible'})` continuously during the navigation. Assert sign-out + user-menu stay rendered for every observed frame.
- Explicit bfcache test: `await page.goBack()`, assert chrome present on the bfcache-restored page.

Closes V2's literal class. ~half-day implementation added to the chrome invariant test.

### CMT-3 — Chrome invariant extends to App Router boundary files

Next.js App Router has special boundary files: `loading.tsx` (Suspense), `error.tsx` (error boundary), `not-found.tsx` (404). These are route-level, rendered by Next.js automatically. Per-flow YAML exercises `page.tsx` but not the boundaries. A future bug like "error.tsx loses chrome" would be undetected.

Extending the chrome invariant: for each authenticated route, walk its boundary files. Slow API → assert `loading.tsx` renders + chrome present. API 500 → assert `error.tsx` renders + chrome present. Bad ID → assert `not-found.tsx` renders + chrome present. Each boundary tested for the SAME chrome contract as `page.tsx`. ~1 day implementation added to the chrome invariant test.

### Inline flagged (no separate decision)

- **`requiresAuth` marker is structural, not behavioral** — meta-test only enforces the export exists; behavior is covered by CMT-2/CMT-3 runtime invariants. Outside voice argued the marker is "theater"; partial validity, but the structural check still has value (catches missing registry entries).
- **JOURNEYS.md auto-generation** — outside voice argued JOURNEYS.md without an executable contract rots into dead documentation. Recommendation: generate JOURNEYS.md from `journey:` tags in flow YAML so it stays in sync. Defer to V1.1 if not done by V1.0 implementation.
- **T1 effort calibration** — original 1-day allotment may extend to ~1.5 days given CMT-2/CMT-3 added test surface. Author should verify before committing.

## Updated W6 / W7 specifications (amendment v1.2)

These supersede the W6 / W7 sections in `eng-review-test-plan.md` amendment v1.1.

### W6 EXTENSION — global authenticated-chrome invariant (updated)

- New test: `e2e/contract/chrome-invariant.spec.ts` (asoe-ui, Playwright).
- Registry: `e2e/contract/authenticated-routes.ts` enumerates every route requiring auth chrome.
- Mechanism: for each route, `page.goto(route)`, assert it renders inside `AuthenticatedLayout` and the layout's chrome contract is intact.
- **Transition stability** (CMT-2): for each `(route_a → route_b)` transition pair, observe chrome continuously during the nav; assert chrome stays rendered for every observed frame.
- **bfcache** (CMT-2): `page.goBack()`, assert chrome present on the restored page.
- **Boundary coverage** (CMT-3): for each route, walk its `loading.tsx` / `error.tsx` / `not-found.tsx`; assert each boundary renders chrome.
- Meta-test: `e2e/contract/auth-route-coverage.spec.ts` scans `src/app/**/page.tsx` for `export const requiresAuth = true`, asserts each is in the registry. Bounds the registry brittleness.
- Cost: ~1.5 weeks added to Lane 2 (was 0.5 week pre-CMT-2/CMT-3).

### W7 — Playwright flow registry (updated)

- New directory: `e2e/flows/<category>/<name>.yaml` (asoe-ui), with `_registry.yaml` at the directory root.
- Categories: `onboard | triage | resolve | signout | recover`.
- Each flow file declares: `kind: golden | regression`, `journey: J1 | J2 | J3`, `entry`, `steps`, `states`, `state_fixtures`, optional `back_target_override`.
- Steps require `keyboard_equivalent` for every mouse action; assert focus restoration on every navigation; assert aria-live announcements via `<StatusAnnouncer>` testid on status changes.
- States exercised per flow: opt-in via `states:` array. Available keys: `loading`, `empty`, `error`, `partial_failure`, `stale`. Opt-out from any state requires justification comment.
- URL assertions prefer `assert_url_equals` when the ID is known; `assert_url_matches` reserved for genuine wildcards (server-generated UUIDs).
- Companion `e2e/flows/JOURNEYS.md` lives at directory root; flow registry references journey IDs. Auto-generation from `journey:` tags recommended for V1.1.
- Runner: build-time codegen (`e2e/flow-codegen.ts`) + zod schema (`e2e/flow-schema.ts`) + generated specs in `e2e/flows-generated/`. Pre-commit hook `flows:gen`.
- Loading-state assertions use deferred-promise route + assert-during pattern (P1).

Initial flow set (one per file, organised by category):

- `onboard/signin-to-home.yaml` — golden, J1.
- `triage/inbox-load.yaml` — golden, J1, J2 — full state matrix on the most-loaded screen.
- `triage/email-order-entry-from-inbox.yaml` — regression (V1), J1 — entry `/inbox`, click email-order-entry item, expect `back-to-customer-inbox`, click it, expect `/inbox/customer`.
- `triage/inbox-item-click-behavior-catalog.yaml` — regression (V3), J1, J2 — declares per-item-type click behavior; undeclared types fail loud.
- `triage/case-to-exception-detail-roundtrip.yaml` — regression (V2), J1, J3 — full forward/back navigation, chrome invariant asserted at every step.
- `resolve/exception-triage-approval.yaml` — golden, J2 — full keyboard path, aria-live on approval.
- `signout/signout-from-each-role.yaml` — golden — chrome present, focus restoration to sign-in.
- `recover/back-from-misroute.yaml` — golden, J3 — recover without data loss.

Cost: ~2 weeks for the new lane (Lane 3) including all design + eng + cross-model additions.

## Failure modes

| Codepath | Realistic failure | Test? | Mitigation |
|---|---|---|---|
| `_registry.yaml` back-target rules | Dev adds new entry path, forgets to extend the rule -> wrong back-target ships | **GAP** — accepted | Meta-test scans `src/app/**/page.tsx` for `<Link>` back-affordance markers, asserts each is covered by a registry rule |

| `requiresAuth` marker theater | Future refactor moves auth to a route group `(authenticated)/`, deletes the export, tests pass silently | Partially covered | Runtime chrome invariant + CMT-2 transition assertions catch behavior; meta-test only catches structural coverage |
