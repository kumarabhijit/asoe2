## Why this doc exists

The sibling `eng-review-test-plan.md` amendment v1.1 closed three real-world UI bugs (V1 context-aware navigation, V2 affordance regression, V3 inconsistent click semantics) by adding a W6 chrome-invariant test and a W7 Playwright flow registry. The amendment was authored from an engineering angle: registry of routes, registry of flows, YAML shape, runner.

A design-eye pass on that amendment surfaced gaps the engineering shape doesn't speak to: how flows are organised, what happens in non-happy-path interaction states, what user journey the flows are anchored to, how the chrome invariant survives a layout refactor, and what the accessibility floor is. This doc captures those decisions so W6 + W7 land at the right altitude.

## Locked decisions

### D1 — Flow registry organisation

**Hierarchical directory + back-target rules at registry level.**

```
e2e/
  flows/
    onboard/
    triage/
    resolve/
    signout/
    recover/
    _registry.yaml          # back-target rules, route -> entry-path map
```

Each flow file declares `kind: golden | regression`. Golden flows protect primary user value; regression flows lock in fixes for V1, V2, V3 and successors. The `_registry.yaml` declares back-target rules generally — destination's back-target = entry-path's parent route — so the next "back button to wrong place" bug can't surface as V4 from a missing per-flow declaration.

### D2 — Interaction state coverage

**State matrix per flow.**

Every flow YAML carries a `states:` block that exercises the screen at every plausible runtime condition:

```yaml
states:
  loading:           # slow API -> assert skeleton, not blank pane
    delay_ms: 2000
    assert_visible: '[data-testid="inbox-skeleton"]'
  empty:             # zero rows -> primary action + explanation
    fixture: empty_inbox
    assert_visible: '[data-testid="inbox-empty-cta"]'
    assert_text_contains: ["You're caught up", "Refresh"]
  error:             # API 500 -> retry affordance
    fixture: inbox_500
    assert_visible: '[data-testid="inbox-error-retry"]'
  partial_failure:   # list loads, one row fails -> degraded gracefully
    fixture: inbox_partial_failure
    assert_visible_count: '[data-testid="inbox-row"]'
    assert_visible: '[data-testid="inbox-row-error-marker"]'
  stale:             # status changed mid-view -> refresh prompt
    fixture: case_status_changed_mid_view
    assert_visible: '[data-testid="case-stale-refresh-prompt"]'
```

V1/V2/V3 were happy-path bugs. The next class lives in these unhandled states. The state matrix shape mirrors the audit-bearing-registry shape from `design.md` — one declarative artefact, generated tests.

### D3 — User journey storyboards

**Companion `JOURNEYS.md` with 3 archetypes.**

Flow registry references journey IDs. Storyboards drive coverage forward-looking, not bug-reactive.

Archetypes:
- `J1` — *new operator, day one.* Has a customer email, doesn't know which page is "the right one." 5s arc: do they orient? 5m arc: can they finish a triage? 5y arc: is the inbox a place they trust?
- `J2` — *peak-load veteran.* 30 cases queued, keyboard-driven, no time for mouse trips. 5s: does the next case load instantly? 5m: do they finish a batch without context switches? 5y: do they reach for this tool first when a critical exception lands?
- `J3` — *recovery-from-misclick.* Mis-routed a case to the wrong queue, needs to back out without losing work. 5s: do they realise the misclick? 5m: do they recover without re-entering data? 5y: does the system make recovery feel safe enough to take risks?

Each storyboard surfaces flows that need test coverage. `J2` produces the keyboard requirements in D6. `J3` produces the back-target rules in D1.

### D4 — AI slop risk

**Prefer `assert_url_equals` over `assert_url_matches` when the ID is known.**

Regex assertions like `assert_url_matches: /exception/.*` mask false-positive matches: a malformed ID like `/exception//` or `/exception/error` will pass. When the test fixture knows the exact expected URL, declare it. Reserve regex for genuine wildcards (e.g. server-generated UUIDs).

### D5 — Design system alignment

**Anchor the chrome invariant on `AuthenticatedLayout`.**

W6 currently asserts "sign-out + user-menu + breadcrumb shell" as loose selectors. A future refactor that renames `<AppShell>` to `<OperatorLayout>` could leave the assertion passing against a phantom selector match while real chrome went missing.

Rule: `tests/contract/test_authenticated_chrome_invariant.test.tsx` mounts each authenticated route and asserts the route renders inside the canonical `AuthenticatedLayout` component (or whatever asoe-ui's actual layout component is named — recon required at implementation time, before W6 lands). The component contract carries the chrome guarantees; the test asserts the contract.

### D6 — Accessibility coverage floor

**Keyboard activation + focus management in every flow.**

Every flow YAML's interactive steps must declare both a mouse action and a keyboard equivalent. Focus restoration is asserted on every navigation:

```yaml
steps:
  - action: click           # mouse path
    selector: '[data-testid="inbox-row-3"]'
    keyboard_equivalent:    # required, parallel path
      key: Enter
      focused_selector: '[data-testid="inbox-row-3"]'
  - assert_focus_on: '[data-testid="exception-detail-heading"]'   # focus moved
  - action: press
    key: Escape
  - assert_focus_on: '[data-testid="inbox-row-3"]'                # focus restored
```

Status changes (case approved, exception resolved, async errors) must trigger an aria-live announcement asserted by the flow. ASOE handles SOX-relevant traffic; a11y is a compliance posture, not a polish item.

Mobile viewport, screen-reader replay, and `prefers-reduced-motion` deferred to V2. Inbox-only keyboard would be cheaper but bets that no compliance audit lands soon — declined.

### D7 — Click modes + empty-inbox contract

**Click modes:** left-click + keyboard activation (Enter / Space) is the floor on every interactive element in every flow. Right-click context menus, multi-select (shift / cmd-click), and drag-and-drop are out of scope for V1; they land per-flow as the underlying UI ships them.

**Empty inbox:** primary action + explanation. An empty inbox is a *moment*, not a void. Test asserts both a CTA (`Refresh`, `View resolved`, etc.) and an explanatory message (`You're caught up`). This is a product decision the test plan makes explicit so the engineering team has something to assert against.

## Updated W6 / W7 specifications

These supersede the corresponding sections in `eng-review-test-plan.md` amendment v1.1.

### W6 EXTENSION — global authenticated-chrome invariant (updated)

- New test: `tests/contract/test_authenticated_chrome_invariant.test.tsx` (asoe-ui).
- Registry: `tests/contract/authenticated-routes.ts` enumerates every route requiring auth chrome.
- Mechanism: for each route, mount it, assert it renders inside the asoe-ui `AuthenticatedLayout` component (name confirmed at implementation), and assert the layout's contract (sign-out, user-menu, breadcrumb shell) is intact.
- Meta-test: `tests/contract/test_authenticated_routes_registry_coverage.test.tsx` scans `src/app/**/page.tsx` for authenticated layout markers, asserts each has a registry entry. Bounds the registry brittleness.
- Cost: ~0.5 week added to Lane 2, runs after W6 baseline lands.

### W7 — Playwright flow registry (updated)

- New directory: `e2e/flows/<category>/<name>.yaml` (asoe-ui), with `_registry.yaml` at the directory root.
- Categories: `onboard | triage | resolve | signout | recover`.
- Each flow file declares: `kind: golden | regression`, `journey: J1 | J2 | J3`, `entry`, `steps`, `states`, optional `back_target_override`.
- Steps require `keyboard_equivalent` for every mouse action; assert focus restoration on every navigation; assert aria-live announcements on status changes.
- States exercised per flow: `loading`, `empty`, `error`, `partial_failure`, `stale`. Each cites its fixture in the asoe2 sandbox-gateway responses or asoe-ui MOCK_* tables.
- URL assertions prefer `assert_url_equals` when the ID is known; `assert_url_matches` reserved for genuine wildcards (server-generated UUIDs).
- Companion `JOURNEYS.md` lives at `e2e/flows/JOURNEYS.md`; flow registry references journey IDs.

Initial flow set (one per file, organised by category):

- `onboard/signin-to-home.yaml` — golden, J1.
- `triage/inbox-load.yaml` — golden, J1, J2 — full state matrix on the most-loaded screen.
- `triage/email-order-entry-from-inbox.yaml` — regression (V1), J1 — entry `/inbox`, click email-order-entry item, expect `back-to-customer-inbox`, click it, expect `/inbox/customer`.
- `triage/inbox-item-click-behavior-catalog.yaml` — regression (V3), J1, J2 — declares per-item-type click behavior; undeclared types fail loud.
- `triage/case-to-exception-detail-roundtrip.yaml` — regression (V2), J1, J3 — full forward/back navigation, chrome invariant asserted at every step.
- `resolve/exception-triage-approval.yaml` — golden, J2 — full keyboard path, aria-live on approval.
- `signout/signout-from-each-role.yaml` — golden — chrome present, focus restoration to sign-in.
- `recover/back-from-misroute.yaml` — golden, J3 — recover without data loss.

Cost: ~1.5 weeks for the new lane, ~0.5 week added by the design-review-locked extensions (state matrix, keyboard floor, JOURNEYS.md). New cost: ~2 weeks for Lane 3.

## Failure modes added by the design-review extensions

| Codepath | Realistic failure | Test? | Mitigation |
|---|---|---|---|
| `_registry.yaml` back-target rules | Dev adds new entry path, forgets to extend the rule -> wrong back-target ships | **GAP** — accepted | Meta-test scans `src/app/**/page.tsx` for `<Link>` back-affordance markers, asserts each is covered by a registry rule |
| `states:` block per flow | Dev adds a flow without `states:` -> coverage hole | Built-in | Schema validator on flow YAML rejects flows missing `states:` for any of {loading, empty, error}; warns on missing partial_failure / stale |
| `keyboard_equivalent` per step | Dev adds a step without keyboard equivalent -> a11y hole | Built-in | Schema validator rejects interactive steps without `keyboard_equivalent` |
| `JOURNEYS.md` drift | UX evolves but archetypes don't -> storyboards lie | **GAP** — accepted | Quarterly journey review on the team calendar; not a CI gate |
| `AuthenticatedLayout` rename | Refactor renames the component, registry reference stale | Build-time | TypeScript import in the test file fails to resolve -> hard error at CI |

**Critical gaps post-design-review: 2** (back-target meta-coverage, JOURNEYS.md drift). Both accepted with documented mitigations.
