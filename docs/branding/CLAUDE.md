# Branding & Trademark Guidelines — CLAUDE.md

## Purpose

This document defines the **branding, voice, trademark, and legal guidelines**
for the company website. Any developer, designer, or content creator working on
the website must follow these rules to ensure brand consistency and legal
compliance.

> **Reference models:**
> - **Vibrium.ai** — Stealth-mode minimal aesthetic, confident positioning
> - **Eudia.com** — "The Enterprise Brain for In-House Legal Teams" — deep
>   enterprise storytelling, named product concepts, domain authority, augmented
>   intelligence philosophy
>
> We adapt Eudia's enterprise-grade branding framework for the **CPG domain**,
> specifically **order-to-cash exception handling**.

### Tagline Guidelines

- Keep taglines to 6–10 words
- Lead with the **domain outcome**, not the technology
- Reference the CPG / order-to-cash space when possible
- Avoid cliches: "revolutionary", "game-changing", "next-gen", "cutting-edge"

**Good examples (Eudia-inspired patterns):**
- "The Enterprise Brain for CPG Operations"
- "AI agents that resolve. Outcomes you can audit."
- "From bottleneck to business driver."
- "Your expertise, codified. Your exceptions, resolved."
- "Augmented intelligence for order-to-cash."

**Avoid:**
- "The next-generation AI-powered solution for everything"
- "Revolutionizing the future of enterprise with AI"
- "AI that does it all" (too vague, no domain authority)

### Brand Name Philosophy

Eudia's name comes from Aristotle's "eudaimonia" (human flourishing). Consider
a similarly meaningful origin story for your brand name:

- Root it in a concept that reflects your mission (operational excellence, clarity, precision)
- Have a one-paragraph origin story ready for the `/company` page
- The name should feel premium, not descriptive (avoid names like "CPG-AI" or "OrderFix")

## 2. Voice & Tone

### Writing Principles

1. **Be direct.** Say what you mean in the fewest words possible.
2. **Be specific.** Use numbers, outcomes, and concrete CPG details over generalities.
3. **Be human.** Write for smart ops leaders, not robots. Avoid corporate jargon.
4. **Be confident.** State facts and capabilities clearly. Don't hedge unnecessarily.
5. **Be honest.** Never overstate capabilities. Stealth mode earns trust through restraint.
6. **Be domain-fluent.** Use CPG terminology naturally — deductions, chargebacks, trade spend, promotional compliance. Your audience knows the space; write for peers, not outsiders.
7. **Be augmenting.** Always frame AI as amplifying human expertise, not replacing it. (Eudia principle: "AI built with you, not for you.")

### Tone by Context

| Context              | Tone                                                      |
|----------------------|-----------------------------------------------------------|
| Hero / Headlines     | Bold, concise, domain-anchored — "The Enterprise Brain for CPG" |
| Platform Page        | Authoritative, architectural — explain the system, not just features |
| Solutions Pages      | Problem-first, empathetic, then confident in the resolution |
| About / Company      | Mission-driven, authentic, with a meaningful origin story   |
| Case Studies         | Data-driven storytelling — challenge → agent → measurable outcome |
| Trust / Security     | Precise, reassuring, certification-backed                   |
| Legal Pages          | Formal, precise, unambiguous                               |
| Blog / Resources     | Thoughtful, educational, opinionated on CPG operations      |
| Error Messages       | Helpful, calm, actionable                                  |
| CTAs                 | Sales-led and specific: "Book a Demo", "Talk to Our Team"   |

### Language Rules

- Use active voice: "Our agents resolve 10,000+ exceptions monthly" not "10,000+ exceptions are resolved"
- Use second person for user-facing copy: "You build. You deploy. You measure."
- Sentence case for headings (not Title Case, except for proper nouns and coined terms)
- No exclamation marks in headlines or body copy
- Oxford comma: always
- Numbers: use digits for 1+, spell out "zero" and "one" in prose
- **Coined product terms** (e.g., "{Brand} Brain", "{Brand} Agents") are always capitalized
- Use "augmented intelligence" over "artificial intelligence" where possible
- Say "resolve" not "fix" — it implies structured process, not ad-hoc patching

### CPG Domain Vocabulary

Use these terms naturally in copy to signal domain expertise:

| Term                       | Context                                       |
|----------------------------|-----------------------------------------------|
| Order-to-cash (O2C)        | The end-to-end process we optimize             |
| Deductions                 | Customer-initiated claims against invoices      |
| Trade spend / trade promotion | Promotional budgets and compliance            |
| Chargebacks                | Disputed charges from retailers                |
| Pricing discrepancies      | Mismatches between agreed and invoiced prices  |
| Credit blocks              | Holds on customer orders due to outstanding AR |
| Duplicate POs              | Redundant purchase orders creating reconciliation issues |
| Margin leakage             | Revenue lost through unresolved exceptions     |
| Shared services            | Centralized operations teams at large CPGs     |
| ERP / SAP                  | Core systems our platform integrates with      |

## 3. Trademark & Logo Usage

### Logo Rules

| Rule                             | Requirement                                      |
|----------------------------------|--------------------------------------------------|
| Clear space                      | Minimum padding = height of the logo mark on all sides |
| Minimum size                     | 24px height for digital, 12mm for print          |
| Background                       | Use on dark backgrounds (preferred) or light with approved variant |
| Modifications                    | Never stretch, rotate, recolor, add effects, or alter the logo |
| Co-branding                      | Logo must always be equal or larger than partner logos |
| Favicon                          | Use the logomark only (no wordmark) at 32x32px and 16x16px |

### Logo Variants

| Variant            | Usage                                |
|--------------------|--------------------------------------|
| Full (mark + wordmark) | Primary — website header, hero, docs |
| Logomark only      | Favicon, app icon, social avatars     |
| Monochrome white   | On dark backgrounds                   |
| Monochrome dark    | On light backgrounds (if light theme) |

### Logo Don'ts

- Do not place the logo on busy/low-contrast backgrounds
- Do not use the logo as a pattern or texture
- Do not add drop shadows, outlines, or gradients to the logo
- Do not animate the logo without brand team approval
- Do not combine the logo with other symbols or text

## 4. Trademark Notices

### On the Website

- First mention of the company name on each page should include the
  appropriate trademark symbol: `™` (unregistered) or `®` (registered)
- Footer must include: `© {YEAR} {Company Name}. All rights reserved.`
- Third-party trademarks mentioned on the site must include attribution:
  `"{Name}" is a trademark of {Owner}.`

### In Legal Pages

The following pages are **required**:

| Page              | URL Path          | Content                                       |
|-------------------|-------------------|-----------------------------------------------|
| Terms of Service  | `/terms`          | Usage terms, liability, governing law          |
| Privacy Policy    | `/privacy`        | Data collection, cookies, GDPR/CCPA compliance |
| Cookie Policy     | `/cookies`        | Cookie types, consent, opt-out                 |
| Trademark Policy  | `/trademark`      | Logo usage, naming guidelines, permissions     |

### Trademark Usage in Copy

- Always capitalize the company name as registered
- Never use the company name as a verb or generic noun
- Never pluralize or possessivize the trademark incorrectly

**Correct:** "Deploy agents with {Company Name}."
**Incorrect:** "{company-name} your workflows." (used as verb)

## 7. Stealth-to-Launch Transition Strategy

Eudia operated in stealth for ~2 years before their $105M Series A reveal.
Plan your website for a phased rollout:

### Phase 1: Deep Stealth (Current)

**What to reveal:**
- Company name, logo, and origin story
- High-level value proposition (1–2 sentences)
- Problem space: "CPG order-to-cash exceptions"
- "The CPG Brain" concept (high-level, no architecture details)
- Social proof: investor logos, client count (no names), aggregate metrics
- Waitlist / "Book a Demo" CTA
- Hiring page (if actively recruiting)
- LinkedIn and Twitter/X links

**What NOT to reveal:**
- Detailed product architecture or technical implementation
- Proprietary algorithms, model details, or the Skill–Shadow–Recipe architecture
- Specific customer names without written permission
- Roadmap or unreleased feature details
- Pricing (until publicly launched)
- Internal metrics not approved for public sharing

### Phase 2: Controlled Reveal (Pre-Launch)

Add to the site:
- Platform page with system diagrams (high-level, not implementation)
- Named product concepts ({Brand} Brain, Agents, Recipes, Shadow)
- 1–2 named customer stories (with permission) — use Eudia's pattern:
  "The {Customer} Brain" with challenge → solution → outcome
- Solutions pages for each exception type
- Trust Center with certifications

### Phase 3: Full Launch

Add to the site:
- Detailed platform architecture page
- Full case study library
- Pricing page
- Integration directory (SAP, Oracle, etc.)
- Blog with thought leadership
- Resource library (whitepapers, industry reports)

### Messaging Framework

```
Layer 1 (Public):    What problem we solve + the "CPG Brain" concept
Layer 2 (Gated):     Platform details behind "Book a Demo" / NDA
Layer 3 (Internal):  Technical architecture, roadmap, financials
```

Only Layer 1 content appears on the public website during stealth.
Layer 2 unlocks progressively as you move toward launch.

## 9. Named Product Concepts — Trademark Preparation

Eudia trademarks coined terms like "Enterprise Brain", "MINDs", "Sigma",
and "Expert Digital Twins". Prepare your coined terms similarly:

| Coined Term (placeholder) | What It Represents                              | TM Status     |
|---------------------------|-------------------------------------------------|---------------|
| **{Brand} Brain**         | Customer-specific knowledge layer                | Prepare ™      |
| **{Brand} Agents**        | Autonomous exception-resolution agents           | Prepare ™      |
| **{Brand} Recipes**       | Deterministic execution playbooks                | Prepare ™      |
| **{Brand} Shadow**        | Compliance approval engine                       | Prepare ™      |

**Usage rules for coined terms:**
- Always capitalize: "{Brand} Brain", not "{brand} brain"
- Use ™ on first mention per page until registered
- Never use coined terms as generic nouns or verbs
- Coined terms must appear consistently across website, docs, and sales materials
- Include all coined terms in the Trademark Policy page (`/trademark`)

Eudia differentiates from "generic AI" by emphasizing domain-specific,
governed, enterprise-grade intelligence. Apply the same pattern for CPG:

| Competitor Type          | How We Differentiate                                         |
|--------------------------|--------------------------------------------------------------|
| Generic AI / ChatGPT     | We are domain-specific, deterministic, and compliance-aware  |
| Manual BPO / shared services | We augment teams, not replace them; 10x faster resolution |
| ERP-native tools         | We sit on top of ERP, not locked inside it; vendor-agnostic  |

**Never name competitors directly on the website.** Use positioning language:
- "Unlike generic AI tools..."
- "Beyond what your ERP can do alone..."
- "More than a point solution..."

## 11. Developer Handoff Notes

- Use CSS custom properties (variables) for all colors, spacing, and typography
- Implement dark theme as default; light theme as optional toggle
- Use a component library approach (e.g., Tailwind + Headless UI, or Radix)
- All copy should be externalized (CMS or JSON) — not hardcoded in components
- Images served via CDN with responsive `srcset`
- Analytics: defer loading, respect Do Not Track
- Forms: validate client-side AND server-side, sanitize all inputs
- No third-party scripts without privacy review
- **Design system:** Build a Storybook-documented component library from day one
- **Animation library:** Use Framer Motion; document all animation specs
- **Multi-page routing:** Plan for the full sitemap from the start (see SKILLS.md §3)
- **CMS-ready:** Structure content for a headless CMS from launch — avoids painful migration later
- **Diagram components:** Build reusable animated diagram components for the "Brain" architecture visuals
