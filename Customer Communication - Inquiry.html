🧠 Feature Spec · ASOE Email Intelligence

Inbound Email Inquiry Agent

An agentic pipeline that detects intent, extracts entities, queries the ERP, and drafts a customer-ready reply — entirely from a raw inbound email.

📄 Functional Spec
🏗 Pre-Build · Planning Phase
🎯 B2B Order Management
⚙️ ERP/SAP Integration
01 · Overview
What this feature does
The Email Inquiry Agent sits inside ASOE's mailbox layer and acts as a first-responder for every inbound customer inquiry — detecting intent, resolving it from live ERP data, and generating a precise, context-aware reply.
💡
Design Philosophy
This agent is not a chatbot. It is a senior analyst that reads the email, pulls the facts, and hands a draft to the CS rep — who reviews and sends. The human remains in the loop on intent, tone, and send decision. Autonomy is graduated and explicit.
🎯
Goals
✓
Reduce MTTR — from hours to minutes for standard inquiries
✓
Eliminate copy-paste — CS rep never manually looks up ERP data
✓
Consistent responses — same data, same format, regardless of rep
✓
Audit trail — every AI inference, lookup, and draft is logged
✓
Graceful escalation — complex or ambiguous cases route to humans cleanly
📐
Scope Boundaries
→
In scope: Inbound email from known customers and buyer contacts
→
In scope: Read-only ERP lookups (no write-back in v1)
✗
Out of scope v1: Auto-send without human review
✗
Out of scope v1: Approval workflows or pricing changes
✗
Out of scope v1: Non-English emails (configurable for v2)
02 · Processing Pipeline
7-stage agentic pipeline
Every email passes through all stages sequentially. Each stage produces a structured artifact that feeds the next.
Stage 01
📥
Email Ingestion
Parse raw email: headers, body, attachments, threading context, sender identity
›
Stage 02
🔍
Sender Resolution
Map sender email → Customer Account → Contacts in CRM/ERP. Flag unknowns.
›
Stage 03
🧭
Intent Detection
Classify inquiry type(s). Support multi-intent. Assign confidence score per intent.
›
Stage 04
⛏
Entity Extraction
Extract order #s, SKUs, dates, quantities, reference #s, PO numbers per intent.
›
Stage 05
🏗
ERP Lookup
Fan-out parallel queries to SAP/ERP based on intent + entities. Structured result set.
›
Stage 06
✍️
Draft Generation
Compose email reply: tone-match, factual data insertion, missing info handling.
›
Stage 07
👤
Human Review & Send
CS rep reviews draft + evidence, edits if needed, approves or escalates, sends.
⚙️
Stage-by-Stage Detail
Inputs → Processing → Output artifact
1
Email Ingestion & Preprocessing
Strip HTML, extract plain text body. Identify thread context (is this a reply in an existing chain?). Extract attachments and flag type (PDF, Excel, image). Identify if it's a forwarded email or a CC'd loop.
InputRaw MIME email via IMAP / webhook / mail relay
Output ArtifactNormalizedEmail { subject, body_text, sender, thread_id, attachments[], in_reply_to }
Edge RiskThread context may override apparent intent; reply-to-all storms
2
Sender Resolution
Match sender email domain → Customer Account in ERP (SAP KNA1 / CRM). Match individual sender → Contact record. Determine account tier, assigned CS rep, active contracts. Unknown senders are routed to manual triage queue immediately.
LookupSAP KNA1 (Customers), KNVV (Sales data), Contacts table
Output ArtifactResolvedSender { customer_id, account_name, tier, sales_org, cs_owner, is_known: bool }
FallbackUnknown sender → queue to manual triage, no AI processing
3
Intent Detection
LLM classifies the email against the intent taxonomy (see §3). Supports multi-intent: a single email may contain a price inquiry AND a shipment status question. Each intent gets an individual confidence score. Low-confidence (<70%) intents are flagged for human confirmation before ERP lookup proceeds.
ModelClaude · structured JSON output · per-intent confidence[0-100]
Output ArtifactIntentResult { intents: [{type, confidence, span}], primary_intent, needs_clarification: bool }
Thresholdconfidence < 70 → flag · confidence < 40 → halt and escalate
4
Entity Extraction
Per detected intent, extract the required entities (order numbers, SKUs, dates, etc.). Entities are validated against ERP format patterns before lookup (e.g., SAP sales order format). Missing required entities for an intent trigger a clarification path — the agent can generate a clarification email draft to send back to the customer asking for the missing info.
ValidationRegex + LLM dual-pass · SAP order format: [0-9]{10} · Material: [A-Z0-9-]{6,18}
Missing entity pathGenerate clarification draft → Human reviews → Sends clarification email
Output ArtifactExtractedEntities { order_numbers[], materials[], dates[], pos[], qty, ref_numbers[] }
5
ERP Lookup (Parallel Fan-out)
For each intent × entity combination, dispatch parallel ERP queries. Results are normalized into a structured lookup response. Partial failures (e.g., one of three orders not found) are handled gracefully — the response draft notes the gap rather than failing entirely.
PatternFan-out → Promise.allSettled() → per-query status + result
Timeout8 seconds per query · retry once · flag partial on second failure
Output ArtifactERPResults { queries[{ intent, entity, status, data, error? }] }
6
Draft Email Generation
LLM generates a structured reply email from the ERP result set. Tone is calibrated to: customer tier, prior email tone, account relationship. The draft is segmented — each answer block maps back to its source ERP data (for the reviewer to verify). Missing data sections are explicitly noted in the draft ("We were unable to locate shipment status for PO-88421 — please see note below.").
Tone inputsCustomer tier · email formality score · prior thread tone · CS rep persona
Output ArtifactEmailDraft { subject, body, evidence_map[{paragraph_id → erp_source}], confidence, warnings[] }
Sensitive dataContract pricing → redaction flag · pricing discounts → require approval flag
7
Human Review & Dispatch
CS rep sees the side-by-side panel: inbound email + evidence card + generated draft. Inline editing available. Reviewer can approve, edit, or escalate. Final send action is always a deliberate human click (v1). Full audit trail recorded: who reviewed, what edits were made, timestamp, final sent body.
Actions availableApprove & Send · Edit & Send · Send Clarification · Escalate · Dismiss
SLA trackingTime-in-queue visible on card · configurable SLA thresholds per customer tier
Audit logEvery field change diffed and stored · AI vs human content tracked separately
03 · Intent Taxonomy
11 supported inquiry types
Each intent has a canonical definition, trigger signals, required entities, and a mapped ERP lookup path. A single email can trigger multiple intents simultaneously.
💲
Price Inquiry
Customer asking what the contracted or current price is for a specific material, quantity tier, or promotion.
"What's our price on SKU-1180 for Q4? Our buyer says we have a deal below $9.50."
material_id quantity date_range?
📦
Product Availability
Is a material in stock? What's the ATP (Available-to-Promise) date? Is there allocation risk?
"Can you confirm 500cs of SKU-3310 available for a Feb 14 ship date? Running a promo."
material_id quantity ship_date
📋
Order Status
Where is my order in the processing lifecycle? Is it confirmed, in picking, blocked, or released?
"Can you check on PO 88421? Our system shows it submitted 3 days ago but no confirmation."
order_number po_number?
🚚
Shipment & Delivery Status
Tracking number, carrier, ETA, POD (Proof of Delivery), or delivery discrepancy investigation.
"Truck was supposed to arrive yesterday. BOL# 7723981. Still waiting at DC."
order_number bol_number? ship_date?
🧾
Invoice & Billing
Invoice copy requests, billing discrepancies, payment terms clarification, credit memo status.
"We're disputing invoice 9040182. The price doesn't match our contract rate."
invoice_number order_number? amount?
↩️
Returns & Credits
Return merchandise authorization (RMA) request, credit memo inquiry, short-ship credit, or quality issue return.
"We received 40cs short on order 88426. Need a credit memo ASAP."
order_number quantity reason?
📝
Contract / Agreement
Questions about active contract terms, validity dates, volume commitment status, or pricing agreements.
"Our contract is up for renewal next month. Can you tell us what pricing tier we're currently at?"
contract_id? material_id?
📄
Document Request
Request for order confirmation, ASN (Advanced Shipping Notice), BOL, COA (Certificate of Analysis), SDS, or sales contract copy.
"Please send the ASN and BOL for PO 88424. Needed for our DC receiving system."
order_number doc_type
🔄
Product Substitution
Customer asks if an out-of-stock or discontinued item has an approved substitute with equivalent specs.
"SKU-0042 is out of stock at our DC. Do you have an approved sub we can use for the display?"
material_id quantity?
📊
Quota & Allocation
What's the remaining quota for a material? Has a promotional allocation been assigned? Are there volume limits?
"How much of the holiday promo allocation do we have left? Want to place a top-up order."
material_id promo_id?
⚠️
Complaint & Dispute
Quality issue, wrong item shipped, damage in transit, deduction dispute. Requires human escalation in most cases.
"We've deducted $4,200 from invoice 9040180. Received wrong product on 3 SKUs."
order_number? invoice_number? deduction_amount?
🔀
Multi-Intent Handling
A single email can carry up to N intents. The pipeline processes each in parallel after extraction. The draft email organizes answers in logical sections — one block per intent — with clear headers. If intents have conflicting or cross-dependent data (e.g., order status + invoice dispute for the same order), they are linked via a shared order context object.
04 · Entity Extraction Spec
Required vs optional entities per intent
Extraction uses a two-pass approach: regex patterns for structured references, then LLM for natural language references (e.g., "last month's shipment"). Missing required entities trigger the clarification path.

Price Inquiry material_id quantity, date_range, sales_org SAP format: 6–18 alphanumeric Send clarification: "Please specify which product you're asking about."
Product Availability material_id, quantity requested_ship_date, plant Qty: numeric · Date: parse natural language → ISO If qty missing → assume 1 unit, flag assumption
Order Status order_number OR po_number line_item, material_id SAP Sales Order: 10 digits · Customer PO: any format Search by customer + date range if no number given
Shipment Status order_number OR bol_number delivery_number, ship_date, dc_location Delivery: 10 digits · BOL: carrier-specific Search open deliveries for customer in last 30 days
Invoice / Billing invoice_number order_number, disputed_amount, invoice_date SAP Invoice: 9 digits starting with 9 Ask for invoice number + approximate amount
Returns & Credits order_number, reason_code quantity, material_id, invoice_number Infer reason from complaint language → standard codes Generate partial return request, flag for CS to confirm reason
Document Request order_number, doc_type delivery_number Doc types: ASN, BOL, COA, SDS, ORDER_CONF, INVOICE If doc_type ambiguous, ask · If order # missing, search recent
Quota / Allocation material_id promo_id, period Promo ID: ZPROM + 6 digits Return all active quota records for customer
Complaint / Dispute One of: order_number, invoice_number deduction_amount, issue_description Deduction: parse "$4,200" or "4200 USD" Always escalate to human — do not auto-draft response

06 · Edge Case Catalog
Known failure modes and handling strategies
Every edge case has a defined behavior. The system never silently fails — it always produces a deterministic outcome with a logged reason.
🔀
Intent
Multi-Intent Email
A single email asks about order status, a shipment ETA, and requests an invoice copy — three distinct intents.
→ Process each intent in parallel. Group ERP results. Generate sectioned reply (each section addressed separately). Flag compound emails in audit log.
❓
Intent
Low Confidence Classification
Email body is vague: "Can you check on our stuff from last week?" — no order # or material specified.
→ Confidence < 70%: surface to CS rep with top-3 intent candidates. Rep selects the correct intent. System continues from Stage 4 with confirmed intent.
👤
Identity
Unknown Sender
Email arrives from a domain not in the customer master, or a new contact at a known account.
→ Route to manual triage queue immediately. No ERP lookup attempted. CS rep verifies identity, creates contact record if needed, then re-processes or responds manually.
🔍
Entity
Ambiguous Order Reference
Customer writes "my order from January" or "the big shipment we had issues with" — no explicit order number.
→ Fuzzy lookup: query recent orders for customer in the implied timeframe. If 1 result: proceed with flag. If 2–5: surface to CS to confirm. If 6+: generate clarification email requesting order #.
📭
ERP
ERP Data Not Found
Customer references order PO-99999 which doesn't exist in the ERP, or a material that's been archived.
→ Generate partial draft: explicitly state data was not found for the referenced item. Flag for CS review. Log lookup miss. Do not invent data or make assumptions.
🔌
ERP
ERP Timeout / System Down
SAP is undergoing batch processing or the middleware is unresponsive. Lookup times out after retry.
→ Mark email with "ERP_UNAVAILABLE" status. Hold in queue. Auto-retry at configured interval (e.g., 10 min). Notify CS rep of hold with reason. Do not send a draft with stale/missing data.
🔒
Data
Sensitive Pricing Disclosure
A price inquiry returns contract pricing that is confidential — e.g., a tiered deal that should not be disclosed without approval.
→ Apply redaction flag from pricing sensitivity config. Draft shows [REDACTED — Requires Approval] in pricing fields. CS rep must obtain authorization before populating and sending.
📎
Input
PDF / Excel Attachment Contains Data
Customer attaches a PO spreadsheet or a PDF dispute letter. Relevant order numbers are in the attachment, not the email body.
→ Extract text from PDF/structured data from Excel (v2 feature). In v1: flag attachment present, prompt CS to manually extract and forward to agent or re-submit with order numbers in body.
♻️
Thread
Reply in Existing Thread
Customer replies to a previous email chain. The new intent is different from the original thread (e.g., original was order status, reply is now about an invoice dispute).
→ Process only the new customer turn, not the thread. Note thread_id for context (e.g., prior order # already known). Detect if the intent has changed from the thread subject.
🌍
Input
Non-English Email
Email arrives in Spanish, French, or another language from a known international customer.
→ v1: Detect non-English, route to manual triage with language flag. v2: Translate → process → generate reply in customer's language. Log language detection in audit.
🚨
Special
Complaint or Dispute Detected
Any email classified as COMPLAINT or DISPUTE — regardless of other intents present. These carry legal and financial implications.
→ Always escalate to human. AI drafts an acknowledgment only ("We've received your message and are reviewing…"). ERP lookup still runs for context, but no substantive AI response is generated. Flag for senior CS or trade ops.
🧹
Special
Spam / Auto-Reply / OOO Detection
An out-of-office autoresponder, a bounce notification, or marketing spam arrives in the monitored mailbox.
→ Pre-filter checks: "Auto-Submitted" headers, OOO keywords, bounce/NDR codes. Classify as SYSTEM_EMAIL → skip pipeline → discard silently, log classification reason. No CS queue entry created.

09 · Open Questions
Decisions needed before build
These are unresolved design decisions that require product, engineering, or business stakeholder input before the sprint begins.
1
Mailbox integration strategy: dedicated inbox vs. BCC routing vs. forwarding rule?
Do we process a dedicated ASOE mailbox (e.g., orders@company.com), do reps BCC emails into the platform, or do we intercept via Exchange/Gmail forwarding rules? Each has different latency, threading, and data privacy implications.
2
Who "owns" the outbound send — the platform or the rep's personal email client?
If we send from ASOE directly (via SendGrid or similar), the From address changes, which customers may notice. If we push the draft back to the rep's Outlook/Gmail for send, we need OAuth + write access to their mailbox. Which is acceptable?
3
How do we handle contract price sensitivity — who can authorize disclosure and how is that signaled?
Not all price data should be auto-included in replies. We need a pricing sensitivity config per material group and customer tier. Who configures this? Is it a Trade Ops function? How is a disclosure override approved?
4
ERP connectivity: RFC / BAPI, OData / REST APIs, or middleware (e.g., MuleSoft, SAP Integration Suite)?
The lookup architecture in §5 assumes we can query SAP tables in near-real-time. What's the actual integration path available? RFC synchronous calls have very different latency profiles from OData APIs or event-driven middleware.
5
SLA targets: what are the target response times per customer tier and intent type?
We need agreed SLA thresholds to drive queue prioritization, escalation triggers, and the autonomy tier unlock conditions. Strategic accounts likely need <2h; standard <24h. Are there SLAs already defined in existing CS contracts?
6
AI cost model: are we tracking per-email token usage and passing to the ASOE billing module?
Given that ASOE already tracks AI call costs for other agents, the email inquiry agent should hook into the same cost tracking infrastructure. Confirm: do we bill tenants per-email processed, or is it included in platform tier pricing?
7
Persona permissions: which ASOE personas can configure autonomy levels vs. can only review drafts?
The existing persona model (Admin, CS Manager, Sr. Analyst, CS Analyst, Trade Analyst) needs to be extended with explicit permissions for: autonomy level configuration, triage queue access, escalation routing, and disclosure approval.
